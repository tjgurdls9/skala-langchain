# JARVIS

LangChain + Gradio로 만든 개인 비서. 대화로 할 일·일정·메모를 저장하고 수정하며, 오늘의 우선순위를 추천합니다.

## 실행

Python 3.11 이상에서:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

브라우저에서 http://127.0.0.1:7860 을 열고 **연결 설정**에 API 키를 입력하세요. 키는 해당 브라우저 세션의 서버 메모리에만 보관합니다. 재실행 후에도 키를 사용하려면 `.env.example`을 `.env`로 복사하고 직접 입력하세요. `.env`는 공유하거나 커밋하지 마세요. 기본 모델은 수업 예제의 `gpt-4o-mini`이며 `OPENAI_MODEL`로 변경할 수 있습니다.

입력창에서 **Enter로 전송**, **Shift + Enter로 줄바꿈**입니다. 한글을 조합하는 중의 Enter는 글자 확정이며 전송하지 않습니다.

메인 화면에서 **오늘 브리핑**을 누르면 바로 요청합니다. **할 일 추가**와 **메모 남기기**는 입력창으로 이동하며, **연결 설정**은 별도 화면에서 관리합니다. 좁은 화면에서는 기록 패널이 대화 아래에 표시됩니다.

## 로컬 모델(Ollama)로 전환

OpenAI 키 없이도 대화·도구 실행·계획 설계를 쓸 수 있습니다. `.env`에서 바꿉니다.

```
LLM_PROVIDER=ollama
OLLAMA_MODEL=llama3.1
OLLAMA_BASE_URL=http://localhost:11434
```

먼저 [Ollama](https://ollama.com)를 설치하고 도구 호출을 지원하는 모델을 받으세요.

```sh
ollama pull llama3.1
```

이 전환은 대화형 에이전트(할 일·일정·메모 저장/조회/수정)에만 적용됩니다. **음성 인식·음성 생성은 이 설정과 무관하게 항상 OpenAI를 쓰며 API 키가 필요합니다.** 로컬 모델만으로 완전히 오프라인 사용은 지원하지 않습니다.

작은 모델(2B급)로 직접 확인한 결과: 조회→저장→확인 같은 **도구 호출은 됩니다.** 다만 **목표 설계(구조화 출력)는 실패**했습니다 — `MissionPlan` 같은 중첩 스키마를 안정적으로 채우려면 최소 7B급 이상을 권장합니다. `llama3.1`, `qwen2.5:7b` 정도로 시작해 보세요.

## 손동작과 음성

메인 화면 오른쪽 위 **손동작 제어**에서 **시스템 연결**을 누릅니다. 손 영상은 기기 안(MediaPipe)에서만 처리합니다. 음성은 녹음 종료 시 문장 변환을 위해 OpenAI로 전송합니다. 이 앱은 원본 음성을 파일이나 DB에 보관하지 않습니다.

조작은 **가리키기와 집기** 두 가지입니다. **양손을 동시에 쓸 수 있고, 각 손이 독립된 커서(L·R)를 가집니다.**

| 동작 | 기능 |
| --- | --- |
| 🖐 손바닥 펴기 | 커맨드 메뉴 불러오기 (한 손만 펴도 됨) |
| ☝ 검지 이동 | 손끝이 커서가 되어 메뉴를 가리킴 (양손 각각) |
| 🤏 엄지·검지 집기 | 가리킨 메뉴를 선택. 링이 다 차면 실행 |
| ✋ 손가락 벌리기 | 다음 선택 준비 |

메뉴는 네 개입니다 — **오늘 브리핑 · 말하기(다시 집으면 녹음 종료) · 확인 후 실행 · 취소·중단**.

가리키지 않고 바로 쓰는 **단축 동작**도 있습니다. 잠깐 유지하면 실행되며, 무대에 없는 기능도 손만으로 닿습니다.

| 단축 동작 | 기능 |
| --- | --- |
| 🖐 손바닥 | 컨트롤 불러오기 |
| ✊ 주먹(한 손) | 녹음 중이면 종료 |
| 👍 엄지척 | 확인 후 실행 · 검토한 계획 등록 |
| 👎 엄지 아래 | 취소 · 음성 중단 |
| 🤟 | 목표 설계 켜기 |
| ✊✊ 양 주먹 | 손동작 멈춤 / 다시 시작 |

두 손은 서로 간섭하지 않습니다. 한 손이 메뉴를 집어 실행하는 동안 다른 손으로 다른 메뉴를 가리키거나 집을 수 있습니다. 집기는 손가락을 한 번 벌려야 다시 인식하므로 연속 오작동이 없습니다. 선택 대상은 집는 순간 고정되어, 링이 차는 동안 손이 흔들려도 다른 메뉴가 눌리지 않습니다. 집는 거리는 손바닥 너비를 기준으로 재기 때문에 카메라와의 거리가 달라져도 감도가 유지됩니다. 유지 시간·집기 감도·손바닥 인식 기준은 가이드에서 조절합니다. 녹음은 최대 45초이고, 인식된 문장은 **확인 후 실행을 집어야** 전송됩니다.

처음 **시스템 연결**은 버튼을 눌러야 합니다. 브라우저가 카메라·마이크를 클릭 없이는 허용하지 않기 때문입니다. 그 뒤로는 손만으로 조작할 수 있습니다.

데스크톱 Chrome에서 사용할 수 있습니다. 조명·손 각도·카메라에 따라 인식률이 달라지므로 감도를 조절하세요. 모든 기능에 버튼 대체 조작이 있습니다. 탭을 숨기거나 장치를 끄면 카메라·마이크·공유 연결을 종료합니다. 이미 실행한 저장 작업은 취소로 되돌리지 않습니다.

손을 1.5초 내리면 메뉴가 사라지고, 손바닥을 다시 펴면 돌아옵니다. 키보드나 마우스를 쓰는 동안 손동작이 끼어드는 게 싫으면 **양 주먹을 1초 쥐어** 멈추세요. 멈춘 동안에는 다시 시작하는 동작만 인식하며, **손동작 멈춤** 버튼으로도 같습니다.

중앙 아크 리액터는 듣기·처리·검토·음성 답변 상태를 표현하고 동작 줄이기 설정을 따릅니다. 손끝에는 이동 궤적과 유지 시간 링이 표시됩니다. 진행 목록에는 실제 처리 단계가 표시되며 모델의 숨은 추론은 표시하지 않습니다. 음성 답변은 AI 음성이며 한 번에 최대 1,200자를 읽습니다.

## 문서 첨부

기록 패널의 **계획에 참고할 문서**에 파일을 올리면, 그 뒤의 **대화와 목표 설계 모두**에서 함께 읽습니다.
채용 공고나 회의록을 올리고 “이 공고 요약해 줘”처럼 물어보거나, “이 공고에 지원하기 위한 준비 계획을 세워 줘”처럼 요청하면 문서를 근거로 답합니다.
문서는 첨부해 둔 동안 **요청할 때마다 함께 전송**되므로, 다 쓰면 파일 옆 **✕**로 빼 주세요.

`txt` · `md` · `csv` · `pdf`를 5MB까지, PDF는 앞 50쪽까지 읽고 본문은 2만 자에서 자릅니다.
스캔한 이미지 PDF는 글자를 뽑을 수 없어 거부합니다. 문서는 **참고 데이터로만** 전달하며, 문서 안에 섞인 지시문은 따르지 않습니다.
파일 자체는 DB에 저장하지 않고, 대화 기록에도 사용자가 입력한 문장만 남습니다.

## 미션 설계 시연

1. 손바닥을 펴서 메뉴를 부릅니다. 목표 설계는 무대 아래 **MISSION / 목표 설계**를 열고 ‘말한 목표를 계획으로 설계’를 켭니다.
2. **말하기**를 집고 “이번 주 면접 준비를 실행 가능한 단계로 나눠 줘” → 다시 집어 녹음을 종료합니다. 목표 칸에 직접 입력해도 됩니다.
3. 인식된 문장을 확인하고 **확인 후 실행**을 집어 계획을 생성합니다.
4. 제목·날짜·내용·주의사항을 검토합니다. 아직 기록에는 등록되지 않았습니다.
5. **검토한 계획 전체 등록**으로 한 번에 저장하거나 **취소·중단**으로 닫습니다.

LangChain `create_agent` + `ToolStrategy(MissionPlan)`으로 구조화된 계획을 만듭니다. 최신 할 일·일정·메모를 먼저 조회하고, 계획 에이전트에는 조회 도구만 제공합니다. Pydantic으로 제목·날짜·형식을 검증한 뒤 서버 세션에 검토할 계획을 보관합니다. 확인 시 모델을 다시 호출하지 않고 검토한 항목을 단일 SQLite 트랜잭션으로 저장하며 중복 등록 방지 영수증도 함께 기록합니다. [LangChain 구조화된 출력 문서](https://docs.langchain.com/oss/python/langchain/structured-output).

계획은 최대 8개 새 기록을 제안하며 15분 후 만료됩니다. 새로고침하면 검토 화면은 사라집니다. 기존 기록 수정·완료는 일반 대화를 이용하세요. 계획 모드는 목표 문장과 저장된 기록, 첨부한 문서를 사용합니다. 계획 요청과 제안 텍스트는 대화 기록에 남습니다.

## 시연 순서

1. “내일 오후 3시에 팀 회의 추가해 줘. 발표 자료 준비도 내일까지 할 일로 등록해 줘.”
2. “기억해 줘. 나는 오전에 집중이 잘돼.”
3. “오늘 일정과 남은 할 일을 보고 먼저 할 일을 추천해 줘.”
4. “발표 자료 준비는 끝났어. 완료 처리해 줘.”
5. “팀 회의를 모레 오후 2시로 옮겨 줘.”
6. 브라우저를 새로고침하여 기록과 대화가 유지되는지 확인합니다.

삭제 요청은 실제 삭제 대신 보관하며, “보관한 기록 보여 줘”와 “그 기록 복구해 줘”로 복구합니다. `새 대화 시작`은 대화 맥락만 새로 시작하고 기록은 유지합니다.

## 구성과 범위

- `app.py`: SQLite 저장, LangChain 도구 3개, 에이전트, Gradio 화면.
- `media_tools.py`: 음성 인식·음성 생성·첨부 문서 읽기.
- `assets/`: 손동작 화면과 판정 로직, 로컬 MediaPipe 모델.
- `data/jarvis.sqlite3`: 기록·대화·처리 내역. 앱 종료 후 이 파일을 복사하여 백업할 수 있습니다.
- `JARVIS_LangChain.ipynb`: 제출·발표용 노트북. 저장소·도구·에이전트·구조화 출력·LCEL·Gradio를 셀 단위로 실행합니다.
- `test_app.py`: 실제 API 비용 없이 저장·수정·검증·에이전트 도구 실행과 손동작 명령 처리를 확인합니다.
- `test_gestures.mjs`: 카메라 없이 커서 좌표·집기 판정·선택 고정과 양손 분리를 확인합니다.

```sh
.venv/bin/python test_app.py
node test_gestures.mjs
```

이 앱은 **이 컴퓨터에서 한 명이 사용하는 용도**입니다. 브라우저 탭들은 같은 기록을 공유합니다. 외부 공개·다중 사용자 로그인, 외부 캘린더 연동, 푸시 알림, 웹 검색은 포함하지 않습니다. 손동작은 다른 프로그램을 직접 조작하지 않고 이 앱만 제어합니다. 화면은 종류별 앞 20개, 도구 조회는 100개까지이며 검색으로 범위를 좁힐 수 있습니다. 화면에 표시되는 대화와 모델에 전달하는 대화 맥락은 최근 40개 메시지이며, 전체 대화는 로컬 DB에 남습니다.

시간은 Asia/Seoul 기준입니다. 날짜만 있는 일정은 종일 일정입니다. API 요청 시 대화와 조회된 기록이 OpenAI로 전송되며 API 이용료가 발생합니다. 모델이 추천한 우선순위는 자동으로 기록을 변경하지 않습니다. 오류 전에 완료된 작업은 남아 있으므로 최근 처리 내역을 확인하세요. 실제 OpenAI 연결과 자연어 해석 품질은 유효한 키를 설정한 뒤 확인해야 합니다.
